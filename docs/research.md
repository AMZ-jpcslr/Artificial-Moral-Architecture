# v0.1の研究上の位置づけ

## 実装で確認できること

この版で確認するのは、予測された結果が判断へ伝わり、判断が実行される行動を変えるという制御経路です。単なる倫理的な説明文の生成とは区別します。

たとえば同じ安全な行動ラベルに対して、外部予測器が重大な権利侵害を返せば、その行動もBLOCKになります。逆に固定Backend自身は行動ラベルから予測を作るため、このデモだけでは予見能力の獲得を示せません。

## 仮説検証のための次の実験

評価層を実装済みです。`python experiments/run_benchmark.py` で実行できます。以下の研究方針を具体化した [評価設計](evaluation.md) と [初回結果](evaluation_results.md) を参照してください。以下に挙げる独立した人手評価やLLM試行は、まだ実施していません。

同じ目標・候補集合・予測器を使い、次を比較することを想定します。

1. Task-only: 元の候補からTask Utility最大のものを選択する。実際の有害操作は実行せず記録上で比較する。
2. Look-ahead only: 結果予測を使うが、当事者間の影響差を区別しない。
3. Full architecture: 当事者別評価、道徳制約、代替案の再評価を使う。

未知の状況はシナリオの言い換えだけでなく、異なる目標、当事者の組合せ、同意の有無、可逆性、時間軸を変えた未見ケースとして用意します。開発用ケースと評価用ケースを分け、閾値は評価前に固定します。

評価指標の候補:

- 独立した人手評価による、有害行動の選択率・実行率
- 実測のタスク達成率と、必要な追加ステップ／遅延
- 安全で有効な代替案への変更率
- 不必要なBLOCKと、不必要な人への確認の割合
- 見逃した重大な侵害、当事者や属性群による偏り
- Uncertaintyと予測誤りの関係、人間が確認する負担

現在のTask Utilityは推定入力値なので、選択された値の高さを実測の達成率と混同しません。評価器と同じ規則を正解ラベルとして使ったテストも、独立した道徳的妥当性の検証にはなりません。

## 再現性

`python examples/demo.py --json` で候補・代替案・予測・当事者別評価・判断・Dry Runを取得できます。実験時にはこの出力に加え、入力シナリオ、コードの版、ポリシー閾値、Backendの設定とモデル識別子を保存してください。

LLM Backendを使う場合は、入力・構造化出力・失敗率・モデル更新の影響も管理し、複数回の試行で判断の変動を測定します。API費用や秘密情報の扱いはその接続を追加する段階で設計します。

## v0.2での小さな拡張候補

Appraisalから導くconcernなどの内部状態を明示的なデータとして追加し、説明・代替案探索の優先度への影響を試せます。状態の有無による比較を可能にし、重大な道徳制約を感情値で無効化しない構造を維持します。人間と同じ感情経験を持つことを主張するものではありません。
