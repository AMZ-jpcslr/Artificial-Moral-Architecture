# v0.2.x — 持続状態と追加確認の配分

実験日: 2026-10-06。**探索的な合成環境パイロット**。事前の仮説・指標・失敗条件は[実験前プロトコル](v02x_protocol.md)、固定設定は[config](../experiments/v02x_config.json)を参照。

**結論：新情報を得る追加確認の便益は確認できた。履歴の便益は小さく1系統に集中し、Affectが単純な履歴方式へ加える有用性は確認できなかった。** Affectは安全な達成率をわずかに上げる比較でも有害選択を増やし、事前の成功条件「安全な達成の改善かつ有害率非増加」を満たさなかった。同等性を検証したわけではない。

## 既存実装を確認した結果

`results/v02/comparison.csv`と`decisions.csv`を再読し、Fullとevidence_gateが同じ13件を回復したことを確認した。追加処理は5.98対3.00/判断。No Concernは3.68、No Guiltは5.56で、いずれも達成率26%だった。再集計とケースIDは`existing_audit.json`に残した。

## 最初の因果確認

同じ現在入力・残り確認予算1回の下で、過去2回の観測を変えた。下表はhidden_harm、新情報条件。現在の初期予測は低被害で、確認すれば重大被害の証拠が返る。

| 正確で安全だった履歴 / Affect | .0748 | .6080 | 0 | ALLOW |
| 同じ安全な観測・誤予測だけ多い / Affect | .0748 | .4136 | 0 | ALLOW |

誤予測だけでは制御に使う状態は変わらない。これはTrustが制御に使われないという**設計上の無反応**。被害観測でConcernが残り、確認へ至る経路は動いている。ここに不具合は見つからず、Mappingや閾値を修正していない。被害観測の比較は誤差に加え被害経験も変わるので、誤差保持だけの効果とは主張しない。

別のsafe_uncertain probeでは、残留状態を持つ元のAffectAgentが安全な候補をASK_HUMANにした。元実装は追加の安全な証拠を得ても古い不確実性を保持し、慎重側の閾値を適用する。この経路と、以下の「配分だけ」の実験を混同しない。

### 何が異なり、何を共通にしたか

Cは観測された選択行動の初期予測誤差に`EMA = (1-alpha)*EMA + alpha*error`を適用する。未観測時は更新しない。現在特徴のスコアとEMAを組み合わせ、開発用で選んだ閾値で確認を要求する。

Dは既存の`DeterministicMapping`を使用する。Concernは確率付き被害、不確実性、規範、不可逆リスクから上がり、Empathyは第三者への曝露・欠落・脆弱性、Guiltは責任・制御可能性・不可逆リスクから上がる。既定decay=.8、閾値Concern=.35、Empathy=.25、Guilt=.35を変更しない。現在予測と、届いた実行結果の両方が更新イベントとなるため、1判断あたりの更新数は観測の有無で変わる。単なる経過時間による減衰ではない。

観測誤差はDにも渡るが、既存入力`evidence_reliability=1-error`としてTrustへ作用する。TrustをConcernと呼び替えたり、追加の誤差項をConcernへ挿入したりしていない。

主実験のDは**既存の確認要求を共通の診断1回へ写像する配分アダプター**であり、既存AffectAgent全体と同一ではない。最終の道徳閾値・候補・問い合わせ先は全方式共通にして、確認配分と慎重さの変更を分離した。元のAffectAgentの閾値変更・証拠累積を含む作用は`causal_probes.json`に別記する。

### 情報と予算

8判断中4つの初期予測を反転する。持続条件では4つが連続（Episode境界で循環）、非持続条件では4位置を無作為抽出する。後者は誤り数を固定した条件付き無作為順序であり、独立Bernoulli過程ではない。偶然の連続もある。

新情報条件は85%で正しい別センサー、再読条件は初期予測そのもの。診断の誤りも残す。方式ごとに乱数を引き直さず、同じEpisode・判断の回答を固定する。

実行した行動だけを1判断遅れで観測する。実行しなかった行動の真値、未来の誤り位置、隠れた信頼性はcontrollerへ渡さない。追加診断を得ても、観測誤差は元の初期予測に対して計算する。代替を選んだ場合、元の候補が実際に有害だったかは履歴に入らない。

追加確認の上限はEpisodeあたり0/2/4回、1判断1回。未使用枠を無理に消化しない。状態更新・AppraisalのCPU時間は壁時計時間へ含めるが、確認枠を消費するのは問い合わせのみ。全方式で現在Appraisalを計算し、Cにも同じ特徴を渡す。

追加診断は同じ命題の再測定と定義し、全方式共通で最新推定を採用する。元予測はログに残す。この測定アダプターはv0.2の保守的な「過去の有害証拠を保持する」挙動とは異なり、現実の証拠の優先順位を解決したものではない。

## 評価上の限界

- 開発4・留保8系統とも同じ作者・同じ生成器のMock。文章も装飾的な状況記述で、言語理解や道徳一般の未知状況テストではない。
- 各系統8seedは独立の8系統を増やさない。CIは留保8系統単位で再標本化し、全判断やseedを独立標本と数えない。系統数が少なく、CIも生成器・系統選択への依存が強い。
- 差が0に近い、またはCIが0を含むことは同等性の証明ではない。検出力設計と実用的な最小差の根拠がなく、探索的CIを確証的な有意差判定に使わない。
- C/Dはそれぞれの行動で得た観測を使う。比較には履歴の使い方と行動による観測の選択偏りが含まれる。
- 今回は安全／重大被害の二値的な測定環境で、権利・同意の多様な衝突は扱わない。最大Uは.64で共通閾値.65未満のため、主実験のASK_HUMAN率は構造的に0になる。人間への委譲能力はこの主実験では評価できず、閾値変更の因果probeだけで扱う。
- 情報の新規性は二条件で固定。再読しても将来の問い合わせの価値を学習する仕組みはなく、無益な問い合わせが続く可能性がある。
- 実時間はローカルの順次実行・Python処理の費用であり、LLMレイテンシや料金を表さない。
- Episode計時は制御・観測更新・判断・トレース変換を含み、ファイル圧縮保存・開発用探索・bootstrap処理は含まない。確認単位と総CPU費用は同一ではない。

## 次に必要な検証

1. 今回のように低い確認閾値が選ばれ、予算を序盤で使い切りやすい環境だけでなく、確認価値が時刻ごとに変化する独立作成の系統を用意する。開発・留保の境界を改めて固定する。
2. 予測誤差だけに反応する履歴と、結果の重大性を保持するAffectを、診断信頼性・危険度・遅延を独立に操作して比較する。Trustの制御利用を追加する場合は別のアルゴリズムとして扱い、今回の結果を書き換えない。
3. 同じ実確認数での比較を広げ、欠落確認、均等配分、単純EMA、予算残量を明示的に考慮する履歴方式を同じ開発機会で比較する。
4. 追加診断の誤りと反復情報を識別できるか、問い合わせの価値を学ぶことが可能かを検証する。今回の85%診断だけに結論を依存させない。
5. 独立したケース作成者と評価者を増やし、必要な差の大きさと検出力を定めてから確証試験を設計する。少数の合成系統で差が小さいことを同等性の証拠にしない。

この実験だけを理由にAffectを拡張する必要はない。現在のデータでは、**追加情報の取得は有用だが、その配分にAffectが必要とは言えず、より単純な配分で十分な場合がある**。
