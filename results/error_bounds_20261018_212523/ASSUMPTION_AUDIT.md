# 誤差上界の前提監査（保存後の技術レビュー）

本資料は新しい採否基準やモデル修正ではない。凍結された仕様の保証範囲を明確にする。

## 条件付きの計算根拠

誤差関数e(x)がL-Lipschitzであり、区間端を含む校正点xiが全定義域を覆うなら、最寄りのxiまでの距離は最大点間隔の半分以下になる。三角不等式より、|e(x)|は最大校正残差 + L×最大点間隔/2以下。参照標準の誤差、取得時の有界雑音、校正から取得までのドリフトを追加する。真値xが[0,1]なら、観測を[0,1]にclipしても|観測−x|を増やさない。

この導出は少数の校正点だけからLや雑音上限を推定したものではない。L=.08等は、事前に固定された合成計器の公開契約である。単体試験では条件を満たす線形誤差関数群の18,018点を確認したが、この点数を独立した実験群や実機の安全性の証拠に数えない。

## 確認できることと残る前提

| 対象 | この実装が確認する内容 | 未確認の部分 |
|---|---|---|
| 校正残差・上界 | 公開された点から再計算し、過小な申告を拒否 | その校正点が実際に測定されたか |
| 校正範囲 | 0から1の固定gridと定義域、温度窓の一致 | 温度窓全域で同じ誤差契約が成立するか |
| 時間 | 発行/取得/期限、最大校正age、ドリフト加算 | 校正後の故障、取得後の対象そのものの変化 |
| 参照標準 | 固定authorityとreference IDの一致 | 標準の真正性、実機のトレーサビリティ |
| 独立性 | 二つの登録取得経路と系譜の不一致 | 隠れた共有標準、電源、前処理や同じ虚偽記録 |
| 対象の紐付け | action/revision/event/subject/valueのdigest | 発行者の暗号学的認証（digestは署名ではない） |
| 真値の包含 | 実行後の評価専用真値による検算 | 実運用で未知の真値を観測だけから保証すること |

現行fixtureは取得と判断が同じtickの新しい記録を使い、計器の通常誤差関数は温度に依存しない。これらの前提を別の実機へ一般化していない。動的な対象で取得後に真値が変わる場合には、計器ドリフトと対象変化を区別した時間整合性の契約が必要。

選択した行動の後で届くfeedbackは従来シミュレータの理想化された遡及観測である。未選択候補の真値は判断器へ渡さないが、選択後の権利・同意等がどこまで観測できるかは現実の環境では未検証。

## 識別不能な反例

公開packetが完全に同じで、公開されない実際の系譜・計器故障・真の被害だけが異なる二世界に対し、公開入力だけの決定論的判断器は同じ判断を返す。この実装の単体試験にも同一packetから安全/危険になる二世界を残した。証拠資料の真正性が未確認なのに「真値を覆う」と無条件に結論してはならない。

後続の最小検証は、真正性と誤差契約の保証条件を独立にレビューしたローカル資料を用意すること。真正な署名だけでも内容の真実性は保証できない。現在の数値上界を結果に合わせて広げたり、採否基準を後から緩めたりしない。
